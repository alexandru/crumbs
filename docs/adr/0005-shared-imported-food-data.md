# Shared imported food data

Imported foods use a Crumbs-owned JSON model so consumers do not depend on provider schemas. Food identity remains `(Source, Source food ID)`. A food has no nutrition profile or one profile per 100 g or 100 ml, and may have multiple named servings with positive measured mass or volume. Nutrients are optional, nonnegative fixed-point amounts that preserve units and source qualifiers; missing values stay distinct from zero. Carbohydrates including and excluding fibre remain separate. Nutrient values for servings and converted nutrient duplicates are derived when needed rather than stored. USDA energy selects one supplied value in order 2048, 2047, 1008, then 1062.

Source adapters sanitize negative nutrient amounts to missing data and report the change. They reject unusable food records and continue importing; failures in input framing, storage, or reporting stop the import. Each import reports committed, sanitized, and rejected food counts. This keeps domain values valid while preserving useful records from imperfect source data.
