# Separate profile overrides from derived values

An optional weekly weight-loss rate is stored independently of weight goal. The rate uses nonnegative kilograms per week; zero requests no deficit. The daily calorie deficit is calculated when a profile is read: `weekly_weight_loss × 7,700 kcal/kg ÷ 7 days`. An unset rate produces an unset deficit, even when maintenance calories are available. The deficit can be calculated without BMR inputs, current weight, or a target weight, and does not change maintenance calories.

The fixed coefficient is a planning estimate. It does not model metabolic adaptation or predict actual weight change. [NIDDK describes the limitations of fixed calorie-to-weight rules](https://www.niddk.nih.gov/research-funding/technology-advancement-transfer/research-materials-licensing/body-weight-simulator-java-applet). See the [profile API](../profiles.md) for the rate and derived response fields.

Profile settings distinguish calculated BMR from a custom BMR value in kcal/day, and a baseline activity preset from a custom fixed daily energy addition. Custom intent is explicit and is never inferred from a cached value. Writable settings are separate from derived cache values such as current weight. Profile responses identify the BMR and baseline activity mode and source, and return their effective values. Profiles may be incomplete: missing calculation inputs produce null derived calorie values, while a custom BMR can be used without those inputs. Clearing a custom BMR returns the profile to calculated mode. Weight goal is stored and returned independently.

Settings include sex, height, partial birth date, timezone, and optional weight goal. For calculations, a missing birth-date month or day is treated as January or day one. Calculated BMR uses Mifflin–St Jeor: `10 × weight_kg + 6.25 × height_cm − 5 × age_years + 5` for male, or `10 × weight_kg + 6.25 × height_cm − 5 × age_years − 161` for female. BMR and maintenance calories are computed from current settings, cached current weight, and the current date in the profile timezone when read, so birthday or profile changes cannot leave a stale BMR. [Cronometer's BMR explanation](https://cronometer.com/blog/breaking-down-basal-metabolic-rate-bmr/) describes the equation and inputs.

Effective maintenance calories equal effective BMR plus the baseline activity addition. Preset additions are 0, 0.2, 0.375, 0.5, or 0.9 times effective BMR for no activity, sedentary, lightly active, moderately active, or very active. A custom activity value is a fixed kcal/day addition. These presets follow Cronometer's [Energy Expenditure guidance](https://support.cronometer.com/hc/en-us/articles/31974307318420-Energy-Expenditure). Current weight is a separate cache maintained transactionally from weight log entries as defined in ADR-0012.
